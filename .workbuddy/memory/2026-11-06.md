用户已自行实现「本地 ollama 分角色 + IndexTTS2 合成」，要查 GitHub 是否有人做过。

**最接近的方案（LLM 分角色 + IndexTTS2）**

- `kermit-r-wood/tts-book` 7★ MIT，Go，LLM 分旁白/对话 + 情绪 + 多音字纠正 + Index-TTS2。
- `ch4ngingstar/one-who-reads-aloud-v2` 1★ MIT，Qwen3-14B(GGUF) + IndexTTS2，**设计文档质量最高**。
- `EllaZhangCA/Text-to-Radio-Drama-based-on-Index-TTS` 3★，IndexTTS2 中文台词抽取 + 参考音色。
- `DrewThomasson/VoxNovel` 378★ MIT，BookNLP 引语归属，**仅英文**，有手动校正台。
- `Xerophayze/TTS-Story` 351★ 许可不明，角色配音库 + 接 IndexTTS 2.5 + Ollama 预处理。

**阅读器内路线**：`nikhilprasanth/Auris` 24★ MIT（OmniVoice + spaCy，仅英文，边读边高亮）；Readest 26k★ 只接 MultiTTS，不做角色分配。

**结论**：所有项目都是「离线导 MP3」流水线，「阅读器内 + 中文 + 实时多角色」是空白，用户的位置有独占性。

**可直接借鉴的工程点**（若继续做多角色朗读）
1. 两段式 diarization：确定性 Python 分段 + LLM 只输出标签并锁 GBNF 语法，禁止 LLM 复述正文（v1 教训：丢句、JSON 碎片漏进音频、慢 4 倍）。
2. IndexTTS2 八维情绪向量（happy/angry/sad/afraid/disgust/melancholic/surprised/calm）+ emo_alpha，一个中性参考音即可。
3. SPEAKER_ALIASES + 同名合并，LLM 必然把同一角色拆成两人。
4. 章节状态机 pending→diarized→tts_done→assembled，断点续跑。
5. 显存冲突：ollama(~9G) 与 IndexTTS2(~8G) 在 12G 卡上不能共存，须顺序加载并轮询 nvidia-smi 确认释放。

**License 注意**：本项目 AGPL-3.0；SonicVale 同为 AGPL 可兼容，MIT 项目可并入但需保留声明，TTS-Story 许可不明需先查。

## 多角色朗读：本机实测与环境

用户已在 `MULTI_ROLE_DEV.md` 跑通最小闭环（4 类角色 narrator/male/female/child + IndexTTS2 逐句合成）。

**硬件**：RTX 3090 24G。ollama(11434) 与 IndexTTS2(8972) 可同时常驻，不必像 one-who-reads-aloud 那样顺序装卸。

**TTS 服务**：`~/software/indextts_server.py` + `~/software/start_indextts.sh`，跑在 `~/comfyui-env`。
只借 ComfyUI 的 `custom_nodes/ComfyUI-Easy-IndexTTS2` 里的 vendored 引擎，**不经过 ComfyUI 图执行**，无需启动 ComfyUI 本体。
- `GET /voices`、`GET /health`、`POST /tts {text, ref}` → WAV 22050Hz
- 单线程 `HTTPServer`（backlog 5），无流式、无并发
- 参考音色来自 `~/software/wav-sample/*.wav`（霸总/大叔/厨娘/病娇/8岁女孩等几十个）
- **bug**：只加载 `.wav`，目录里的 `.mp3` 全部被忽略
- **未用能力**：`ENGINE.generate()` 支持 `emo_vector`(8维)/`emo_weight`/`num_beams`/`return_subtitles`，当前全用默认值且 `_subtitle` 被丢弃

**实测 RTF（num_beams=3 默认，22.05kHz）**

| 字数 | 生成 | 音频 | RTF |
|---|---|---|---|
| 10 | 1.19s | 1.97s | 0.60 |
| 37 | 3.60s | 7.52s | 0.48 |
| 70 | 6.88s | 14.52s | 0.47 |
| 142 | 12.49s | 26.78s | 0.47 |

结论：生成速度约为实时 2 倍，稳态边播边生成无压力；瓶颈是首句延迟和角色粒度，不是显卡。
